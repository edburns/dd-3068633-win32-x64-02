## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Serial orchestration was correct.** The dependent factorial task began only after the Fibonacci PR merged to the campaign base.
- **Review convergence was strong.** Each task required one remediation batch and then reached a zero-finding follow-up review.
- **Final gates were evidence-based.** Merge decisions used review IDs tied to the current head, actionable-comment counts, unresolved-thread counts, CI state, exact base/head checks, and explicit refusal detection.
- **Regression protection increased.** Review remediation grew the final suite to 18 passing tests while preserving the original positional Fibonacci invocation.
- **Control isolation held.** Lesson propagation remained off, and the empty campaign lesson file was not used to influence later work.

### 8.2 What Could Improve

- **Token observability is incomplete.** JSONL export included AIU checkpoints but no input/output token fields. Post-mortem tooling should treat AIU and tokens as independent optional measurements and report each without assuming both exist.
- **Review metrics are not emitted directly.** Findings and rounds had to be reconstructed from session prose and review IDs. Stage 40 should persist a small structured outcome record containing review IDs, findings per round, final head, unresolved-thread count, tests, and merge SHA.
- **GraphQL scalar handling was brittle.** The transient thread-ID formatting error should be prevented by explicit scalar extraction and validation before mutation.
- **Campaign overhead should be recorded.** Session exports explain 36m 52s of the 38m 19s run. The orchestrator should record per-transition timestamps so the remaining 1m 27s can be attributed exactly.

### 8.3 Recommended Script and Skill Changes

1. Emit a per-task stage outcome JSON with phase duration, PR number, review rounds, comments per round, test summary, final review ID, final head SHA, merge SHA, and result.
2. Validate GraphQL IDs with a non-empty scalar-string assertion before sending review-thread mutations.
3. Include token fields in export telemetry when available; retain `totalNanoAiu` and `totalPremiumRequests` as separate canonical measures.
4. Preserve the current review-refusal, current-head, CI, unresolved-thread, and base-branch gates; they prevented success-shaped completion without evidence.
5. Use this control run as the baseline for lesson-propagation comparisons: 38m 19s elapsed, 315.63202 AIU, four review rounds, five initial findings, and two clean follow-up reviews.
